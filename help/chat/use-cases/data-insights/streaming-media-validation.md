# Coworkerでストリーミングメディア実装を検証する

Coworkerには、Edge Network上のAdobe Streaming Media （ビデオおよびオーディオ分析）の実装を確認し、Customer Journey AnalyticsやAdobe AnalyticsにフィードするStreaming Media Validation スキルが含まれています。 Assurance、データセット設定、XDM スキーマフィールドグループ、Customer Journey Analytics データビューの設定、生のネットワークログを手動で相互参照する代わりに、1つの検証レポートを取得します。

ストリーミングメディアトラッキングを実装またはトラブルシューティングする場合は、このスキルを使用して、実装が正しく設定されていることを確認し、予想どおりにデータを収集し、追跡する意図をキャプチャします。これらはすべて、Coworker Chatの会話で行うことができます。

>[!NOTE]
>
>次の点に留意してください。
>
>* このスキルは、カスタム実装またはアップグレードの手順（[Coworkerによる実装の計画](./implementation-guide.md)を参照）、実装（[Coworker プロジェクトによる実装チェックリストの生成](./intelligent-checklist.md)を参照）、検証（このスキル）という、より大規模でオプションのワークフローの一部です。 3つのステージすべてを使う必要はありません。 例えば、計画やチェックリストを作成することなく、ストリーミングメディアの実装を検証できます。
>* このスキルは、問題を検証し、診断します。 設定やデータは修正されません。 その結果を使用して、独自の修復を導きます。

このスキルを使用して、以下を行います。

* データストリーム、XDM スキーマ、データセット、Customer Journey Analyticsデータビューをまたいで設定監査を実行し、最初の破損したチェックポイントが原因としてフラグ付けされます。

  この機能は現在、限定提供です。

* 特定のビデオセッション IDを検証し、どのホップ、データセットの取り込み、またはCustomer Journey Analytics マッピングで不一致が発生したかを正確に確認します。

* ライブ Assurance セッションを必要とせずに、アップロードされたCharlesまたはHAR ログ、またはシンプルなURL リストからセッションを検証します。

  この機能は現在、限定提供です。

* 設定をロールアップし、最近のセッションのサンプルを含む、1つのプロンプト（セッション IDやログは必要ありません）で、全体的なヘルスチェックを実行できます。

## 始める前に

<!-- FLAG: General access prerequisite is inferred, not stated explicitly in source docs. Per-mode inputs (session ID, log file) are directly sourced from Functional Requirements. -->

### 必要な情報

ストリーミングメディアの実装を検証するには、次のことが必要です。

* 組織のAdobe Experience PlatformとCustomer Journey Analytics データが接続された状態でWorkfrontにアクセスします。

* セッション ID検証の場合、確認するビデオセッション ID。

* ログベースの検証の場合は、CharlesまたはHARのログファイル、または.txt、.mdまたは.json形式のシンプルなURL リストを使用します。

設定監査や全体的なヘルスチェックに特定の入力は必要ありません。 Coworkerは既存の設定を読み取り、最近のセッションを自動的にサンプルします。

### 制限事項

このスキルを使用する前に、次の点に注意してください。

* **診断のみ**：このスキルでは、設定やデータは修正されません。 問題を特定し、変更を加えます。
* **ストリーミングメディアのみ**：このスキルでは、Edge Networkでのストリーミングメディアの実装について説明します。 メディアデータセット以外のデータセットや、webまたはアプリのAnalyticsの標準の実装は、他のCoworker検証スキルでカバーされています。
* **オンデマンドのみ**：このスキルでは、リアルタイムまたは継続的な監視は提供されません。 継続的なアラートではなく、チェックが必要な場合に実行します。
* **組み込みweb クローラーなし**：このスキルでは、サイトまたはアプリがクロールされません。 クロール範囲を検証する場合は、web クローラーまたはヘッドレスブラウザー出力を証拠として提供します。
* **Edge Network実装のみ**：従来のMedia SDKとAnalyticsのみの実装パスはサポートされていません。
* **より広範な機能はまだ含まれていません**: ライブイベントおよびハートビートストリームの検証、お客様のプレイブックまたはシナリオの検証、マルチプラットフォームの履歴ダッシュボードのロールアップ、ダウンストリームのReal-Time CDPまたはAdobe Journey Optimizerのアクティベーションの検証は、後のリリースで計画されます。

## 検証セッションを開始

1. Coworkerにログインします。

1. [!UICONTROL **新しいチャット**]&#x200B;を選択します。

1. テキストフィールドに、検証する内容を記述します。 次に例を示します。

   **プロンプト**

   > ビデオセッション ID #123を検証します。

   リクエストは、一致する検証モードを実行するストリーミングメディア検証スキルにルーティングされます。

1. （条件付き）セッション IDやログファイルなど、スキルにより多くの情報が必要な場合は、必要に応じてスキルを提供します。

## 検証モードを選択

ストリーミングメディア検証スキルには、4つのモードが含まれます。

### 設定監査

この機能は現在、限定提供です。

XDM スキーマ、データセット、あらゆるData Prep ルールまたはCustomer Journey Analytics派生フィールドを含む、データストリームからCustomer Journey Analytics データビューまでのAdobe Experience Platform フロー全体を検証します。 Coworkerは、ホップごとの合格/失敗スコアカードを報告し、最初のチェックポイントが破損している可能性が高い原因としてフラグを立てます。

プロンプトの例：

* データビュー、データセット、データストリームのストリーミングメディア設定を検証します。
* ストリーミングメディア設定をエンドツーエンドで確認します。
* Media Analytics データストリームがCustomer Journey Analytics用に正しく設定されていますか？

### セッション IDの検証

特定のビデオセッションのCustomer Journey Analytics Data Viewに対してAdobe Experience Platform データセット行をクロスチェックし、ギャップがデータセット取り込みの問題かCustomer Journey Analytics マッピングの問題かを特定します。

プロンプトの例：

* ビデオセッション ID #123を検証します。
* なぜabc-123がCustomer Journey Analyticsに現れないのか？
* データセットとCustomer Journey Analytics データビュー間のセッション xyzを比較します。

### ログベースの検証

この機能は現在、限定提供です。

アップロードしたCharlesまたはHAR ログから、またはシンプルなURL リストから、ライブセッションを必要とせずにセッションを検証します。 Coworkerは、エンドポイントパターン、応答コード、イベントシーケンス、およびping ケイデンスを検証し、完全な信頼性で実行されたチェック、信頼性の低下、またはスキップされたチェックをステートします。

プロンプトの例：

* ストリーミングメディアデータの添付されたログを検証します。
* セッション ID #456については、このCharles ログを参照してください。
* このURLのリストを予想されるメディア pingに対して検証します。

### 検証ダッシュボード

単一のプロンプトで、全体的なヘルスチェックを実施。 Coworkerは、設定監査と軽量でサンプリングされたセッションチェックを1つのステータスにロールアップし、ログが提供されなかった場合にログベースのチェックが実行されなかったことを明確に示します。

プロンプトの例：

* ストリーミングメディアデータの確認：
* ストリーミングメディアの実装に関するレポートを受け取る。
* ストリーミングメディアの実装全体の健全性はどの程度か？

## 結果を見る

各モードは、検証に適した形式で結果を返します。

**構成監査の結果**

データストリーム、XDM スキーマ、データセット、Customer Journey Analytics データビュー、データ準備または派生フィールドルールをカバーするホップごとの合格/失敗スコアカード。 Coworkerは、最初の失敗したホップを可能性の高い根本原因として特定します。

**セッション ID検証結果**

セッション ID、コンテンツメタデータ、イベントタイプ別の行数、主要な指標の値、整合性メモなどを含む、Customer Journey Analytics専用のレポート概要。 ギャップがある場合は、データセットの取り込み時とCustomer Journey Analyticsのマッピングステップのどちらで発生したかを識別します。

>[!NOTE]
>
>セッション IDと認証済みIDの値は、デフォルトで、書き出されたサマリーまたは共有されたサマリーから除外されます。

**ログベースの検証結果**

エンドポイントパターン、応答コード、イベント順序、ping ケイデンスをカバーする、アップロードされたログの構造的および順序付けの検証。 Coworkerは、完全なログキャプチャを提供したか、より単純なURL リストを提供したかに基づいて、どのチェックが完全な信頼性で実行されたか、どのチェックが信頼性が低下して実行されたか、どのチェックがスキップされたかを示します。

**ダッシュボード結果**

「設定+使用可能なデータ」というラベルが付いた単一の統合ステータス。設定監査の結果と、最近のセッションのサンプルチェックを組み合わせたものです。 どのセッションがサンプリングされたかを同僚が指定し、ログが提供されなかったため、ログベースのチェックが実行されなかったことを明確に示します。

## 検証の動作

各モードは専用エンジンにマッピングされます。

* **Configuration Validation Engine**: データストリーム、XDM スキーマ、データセット、Customer Journey Analytics データビューの設定を読み取り、固定されたチェックポイントのセットに対して評価します。
* **Session Cross-Check Engine**：セッション IDが指定され、データセットとCustomer Journey Analytics データビューを照会し、そのセッションの予想される行数と種類を計算し、各ホップで実際の結果を比較します。
* **ログパーサーとバリデータ**：アップロードされたログまたはURL リストを解析し、リクエストの順序とタイミングを再構築して、構造的、順序付け、ネットワーク層のチェックを適用します。
* **ダッシュボード集計エンジン**：構成検証エンジンとセッション クロスチェック エンジンのサンプル実行を実行し、セッション ID、ログ、プレイブックを提供していない場合に、それらを単一のステータスに組み合わせます。
