# Experience Platformの異常値の検出

[!DNL Adobe CX Enterprise Coworker] チャットを使用して、サポートされているAdobe Experience Platform指標の急増と減少を特定します。 データフローとオーディエンスを確認し、ベースラインからの偏差を特定します。

大まかな質問から始め、注意が必要なフローやオーディエンスに焦点を当てます。 何を調査するかを決める前に、報告された指標とそのベースラインを確認します。

>[!AVAILABILITY]
>
>異常値検出の利用は限られています。 一般公開は2027年第1四半期の予定です。

>[!NOTE]
>
>異常値検出は、データや設定を変更することなく情報を提供します。

## 利用可能な診断スキル

`baseline-anomalies` プラグインを使用して、異常値の検出、トレンドの比較、フローの正常性または現在のジョブ失敗の確認を行います。 プラグインは、デフォルトで[!DNL Coworker]のExperience Platformとアプリの機能で設定されます。

必要な情報にもとづいて質問の種類を選択します。

| スキル | 目的 |
| --- | --- |
| [!UICONTROL &#x200B; ベースライン異常値検索フローの異常値] | 取り込み、セグメンテーション、書き出し、宛先の各段階において、記録的な量の急増や減少、失敗したレコードを検出できます。 |
| [!UICONTROL &#x200B; ベースラインの異常値検索オーディエンスの異常値] | 実現したオーディエンスプロファイル数の急増または急減、および終了したプロファイル数の急増を検出します。 |
| [!UICONTROL &#x200B; ベースラインの異常値によるフロートレンドの要約] | 異常値を検出せずに、最近のフロースループットと典型的なフロースループットを比較できます。 |
| [!UICONTROL &#x200B; ベースラインの異常値によるオーディエンスの傾向の要約] | バッチセグメント化について、異常値の判定や予想範囲を使用せずに、最近のプロファイル数と典型的な適格プロファイル数および離脱プロファイル数を比較します。 |
| [!UICONTROL &#x200B; ベースラインの異常値によるフローの正常性の調査] | 重複排除された成功および失敗した実行カウント、および失敗したレコードの合計をアクティビティまたはフロー別に確認します。 |
| [!UICONTROL &#x200B; ベースライン異常値検索で失敗したジョブ &#x200B;] | 復元された失敗と個々のレコードの詳細を除いて、現在失敗したジョブとその失敗理由を確認します。 |

トレンドサマリーは変化を記述しますが、その変化が異常かどうかを判断するものではありません。 スパイクまたはドロップの評価が必要な場合は、異常値の質問を使用します。

## 始める前に

プラグインはデフォルトで設定されています。 診断に関する質問を行う前にステータスを確認するには、次の手順に従います。

1. **[!UICONTROL カスタマイズ]**&#x200B;に移動します。

1. 「**[!UICONTROL プラグイン]**」を選択します。

1. **[!UICONTROL baseline-anomalies]**&#x200B;を開き、ステータスが&#x200B;**[!UICONTROL Active]**&#x200B;であることを確認します。

確認したいサンドボックスと領域を特定します。 特定のリソースの場合、フロー、セグメント、宛先名または識別子の準備ができていること。

一般的なチャットの手順については、[&#x200B; チャットの基本を学ぶ](/help/chat/ui-guide.md)を参照してください。

## 異常値について質問

確認する領域またはリソースと、確認する期間を記述します。

次のプロンプト例をベースに作成します。 例の名前を組織の名前に置き換えます。

| 目標 | プロンプトの例 |
| --- | --- |
| サポートされている領域を確認する | 過去24時間に異常値はありますか？ |
| 取り込みを確認 | 過去24時間に取り込んだデータに異常はありますか？ |
| 特定のフローを確認する | 過去24時間の取り込みフローCustomerImportに異常はありますか？ |
| セグメント化を確認 | 過去24時間のセグメント化に異常はありますか？ |
| 特定のセグメントの確認 | 過去24時間にセグメントロイヤルティメンバーに異常はありますか？ |
| 宛先のアクティブ化を確認 | 過去24時間に宛先のアクティベーションに異常はありますか？ |
| 実現したプロファイルスパイクの確認 | 現在、実現プロファイルが急増しているオーディエンスはいますか？ |
| 失敗したレコードの異常値の確認 | 失敗したレコードは、フローCustomerImportで異常に高くなりますか？ |

この大まかな質問は、データフローとオーディエンスの両方をチェックします。 応答で特定されたサンドボックスと期間を確認します。

## 異常値の結果の確認

報告された値と、影響を受けるリソースと期間のベースラインを比較します。 異常を確定済みの原因として扱うのではなく、その違いを利用して、さらに調査が必要なものを特定します。

例えば、取り込み入力レコードの減少は、ボリュームの変化を識別します。 この変化だけでは、なぜ記録が少なくなったのかは説明できない。

結果は、表または手書きの要約として表示できます。 テーブルは、[!UICONTROL 高リスク &#x200B;]および[!UICONTROL Medium リスク &#x200B;]の下で異常値をグループ化できます。

![異常値の結果グループの取り込みと宛先ボリュームのスパイクとドロップが高リスクおよび中リスクで発生し、リソース名と値が墨消しされます。](assets/anomaly-detection/anomaly-detection-results.png){width="900" zoomable="yes"}

この例では、フローの異常値をリスクごとにグループ化し、実行数またはトレンド履歴を調査することを提案します。 リソースの名前と値が編集されます。

| 結果の詳細 | レビューすべきもの |
| --- | --- |
| [!UICONTROL いつ（UTC） &#x200B;] | 協定世界時のイベント時間または時間ウィンドウ。 |
| [!UICONTROL &#x200B; ステージ &#x200B;] | 取り込みや宛先など、影響を受ける処理ステージ。 |
| [!UICONTROL &#x200B; フロー] | 名前または識別子で識別される、影響を受けるフロー。 |
| [!UICONTROL 何が起こったのか] | ボリュームのスパイクまたはドロップなどの変化が検出されました。 |
| [!UICONTROL 実際と想定される] | ベースラインまたは期待範囲と比較した観測値。 |

説明とリスクグループを確認します。 オーディエンスの異常値の場合、「高」は通常の値から大きく離れていることを示します。 Mediumは、明確だが適度な出発を示している。 HighおよびMediumの異常値のみが返されます。

ベースラインの履歴が変動しやすい場合、オーディエンスの結果からMediumの異常値が除外されます。 したがって、非常に変動する履歴を持つ返された異常値は、高リスク層を持ちます。

根本原因を特定するのではなく、リスク層を利用して調査の優先順位を付けます。

たとえば、1つの応答では、1～4の予想される範囲に対する10の入力レコードが、中程度のリスクスパイクとして識別されます。 通常のレベルは約1 レコードであるため、ベースラインに対する偏差は大きくなります。 絶対量は小さいままです。

過去の異常値を現在の問題として扱う前に、イベント時間を確認します。 過去24時間以外のイベントは、基礎となる状態が回復したかどうかを確認しません。

### ベースラインと期待範囲

時間別の異常値比較では、過去14日間と同じ時間を使用します。 これは、典型的なパターンを時間ごとに説明しますが、より広範な季節性を考慮していません。

オーディエンスの異常値の場合、予測範囲は中央値に重点を置き、履歴数の変動に応じて広くなります。 計算された下限が負の場合、範囲では代わりに最小の履歴カウントが使用されます。 したがって、範囲は中央値よりも中央値より上に広がることができます。

予想される範囲を超える実際のプロファイル数はスパイクです。 範囲を下回るカウントはドロップされます。 プロファイルが通常存在する場合、カウントが0になると、高いリスクが低下します。

離脱したプロファイル数は、スパイク判定のみを生成します。 ドロップの異常値ではなく、通常どおりに処理される出口が少なくなります。

### 返された異常値はありません

リクエストされたオーディエンスおよび期間に対して、高またはMediumの異常値が返されなかったことが応答で報告される場合があります。

![&#x200B; オーディエンスの異常値の概要では、168時間を超える高い異常値またはMediumの異常値は報告されず、除外された履歴に関する警告が含まれます。](assets/anomaly-detection/anomaly-detection-no-anomalies.png){width="900" zoomable="yes"}

この例では、履歴が不十分または大部分がゼロであることを示す警告が含まれています。 すべての時間が評価されたか、このオーディエンスが除外されたかは確認されません。 オーディエンス名とIDが墨消しされます。

### ベースライン履歴が不十分

ベースライン履歴は、オーディエンスを異常値で評価できるかどうかに影響します。

オーディエンスの異常値検出では、5日未満の履歴または履歴がほとんど0を含む行は評価されません。

>[!IMPORTANT]
>
>報告された異常値がないからといって、すべてのリソースが評価されたわけではありません。 オーディエンスが評価されたかスキップされたかは、応答で確認できない場合があります。

## 質問を調整

次の質問は、影響を受けるリソースに集中してください。 たとえば、幅広い取り込みチェックの後、名前付きフローの異常について尋ねます。

過去24時間について質問した後、このフォローアップで期間を延長します。

```text
What about in the past two weeks?
```

過去24時間以内に発生しなかった過去の異常値も応答で特定できます。

詳細な調査については、フローの実行数、フローの傾向、オーディエンスの傾向、現在失敗しているジョブなどについて問い合わせてください。 また、調査中に個々のジョブについて質問することもできます。

必要な情報にもとづいて次の質問を選びましょう。 トレンドと健全性の要約では、異常値の評決は提供されません。

| 目標 | プロンプトの例 | 何を期待するか |
| --- | --- | --- |
| オーディエンスのトレンドを見る | この1週間でオーディエンスはどのように変化しましたか？ | バッチセグメント化の最近のプロファイル数と一般的な適格プロファイル数および離脱プロファイル数（予想される範囲なし）。 |
| フローのトレンドの確認 | 過去1週間で取り込み量はどのように変化したか？ | 異常値を検出せずに、一般的なスループットと比較した最近のスループット。 |
| フローの正常性の確認 | 過去24時間に取り込みフローに対して成功または失敗した実行の数 | 重複排除された実行カウントと、失敗したレコードの合計を集計します。失敗の理由はありません。 |
| 失敗したジョブの調査 | 過去24時間に失敗した書き出しジョブとその理由は何ですか？ | 最新の状態がリクエストされたスコープ内で失敗したジョブで、ジョブの失敗理由が発生します。 |
| フロー失敗の調査 | フローCustomerImportのエラーは何ですか？ | 個々のレコードの詳細を含めずに、フローに関連付けられた現在失敗したジョブの失敗の理由。 |

オーディエンスの傾向履歴は、約2週間、つまり336時間にわたって保持されます。 典型的な値は、過去14日間のその時間の中央値です。

現在失敗したジョブの場合、空の結果は、リクエストされたスコープ内で現在失敗しているジョブがないことを意味します。 これは、要求された期間にエラーが発生しなかったという意味ではありません。 失敗した後に成功したジョブは除外されます。

ヘルスチェックスキルを使用して調査を継続するか、アラートスキルを使用して、サポートされているアセットのアラートを有効にします。 これらのアクションでは、異常値検出そのものではなく、個別のスキルを使用します。

関連するアラートワークフローについては、[顧客アラートスキル &#x200B;](/help/chat/use-cases/customer-alerts/customer-alerts.md)を参照してください。

## 指標の参照

限定リリースには、取り込み、セグメンテーション、宛先アクティベーションに関する次の7つの指標が含まれています。 この参照を使用して、各領域に関連付けられているカウントを特定します。

| 面グラフ | 指標ID | 計数 |
| --- | --- | --- |
| 取り込み | `input_record_count` | 取り込みフローの入力レコードの数。 |
| 取り込み | `failed_record_count` | 取り込みフローで失敗したレコードの数。 |
| セグメント化 | `__segment_{segment_id}__realized_profiles` | セグメントに適格なプロファイルの数。 |
| セグメント化 | `__segment_{segment_id}__exited_profiles` | セグメントを終了するプロファイルの数。 |
| 宛先のアクティブ化 | `{destination}_input_record_count` | 宛先の入力レコードの数。 |
| 宛先のアクティブ化 | `{destination}_skipped_record_count` | 宛先のスキップされたレコードの数。 |
| 宛先のアクティブ化 | `{destination}_output_record_count` | 宛先の出力レコードの数。 |

## 範囲と制限

異常検知機能を利用して異常値を特定します。根本的な原因の確認やリソースの修復を目的としたものではありません。

名前または識別子を使用して、フロー、セグメント、宛先について質問できます。 フロー異常値検出では、取り込み、セグメンテーション、書き出し、宛先の各ステージに対応しています。

現在失敗しているジョブとその失敗理由に対して、失敗したジョブスキルを使用します。 復元されたエラーは除外されます。 ジョブ診断には、個々のレコードや異常値の判定の詳細は含まれません。

フローの正常性は、失敗の理由ではなく集計カウントを提供します。 トレンド概要は、異常値の判定ではなく、最近のデータと典型的な値を記述します。 オーディエンスのトレンドの要約は、バッチセグメンテーションのみを対象としています。

異常値検出は、データや設定を変更しません。 サポートされているアラートアクションとディープヘルス調査に対して、個別のスキルを使用します。
